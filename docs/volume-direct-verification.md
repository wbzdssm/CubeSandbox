# Volume 直通读取：整体验证流程

日期：2026-11-02。本文按 [直通实现方案](volume-direct-access.md) 组织端到端验证步骤，
用于评估“不启动沙箱读取已有卷”是否真正成立。协议与返回结构以
[E2B Volume 合同](e2b-volume-contract.md) 为准。

验证必须区分两类结论：**SDK 是否正确直发协议**，以及 **服务端是否在不启动
沙箱/VM/容器的前提下安全读取真实卷**。前者可用当前测试证明，后者必须由服务端
观测和专项安全测试证明。

## 0. 前提与准备

准备一个**已有卷**，其中包含一个稳定文件，并记录：

- 卷 ID、内容网关地址、有效卷级读取凭证。
- 一个稳定的卷内文件路径。
- 该文件的预期 SHA-256，用于判断读到的数据确实正确，而不只是接口返回 2xx。
- 如有管理面验证需求：管理地址及服务要求的管理凭证。

凭证只通过环境注入，不写入文件、命令行或提交内容。非本机网关须使用 HTTPS。

准备一个**可观测环境**：服务端日志/指标需能显示卷挂载租约获取与释放，以及是否
存在沙箱、VM、容器创建记录。没有观测就无法断言“未启动沙箱”。

## 1. 阶段一：本地回归（不需要网关）

在 `sdk/python`：

```sh
python3 -m pip install -e '.[dev]'
python3 -m pytest -q tests/test_volume.py tests/test_volume_content.py tests/test_volume_direct_harness.py
```

验证：管理响应校验、模型形状、本地 HTTP 协议、同步流行为；回环网关在同一套
E2E 用例下验证只读与写入模式及清理逻辑。

通过标准：全部用例通过。**这只能证明客户端脚本与协议处理正确，不能证明生产
网关可用。**

## 1.5 真实 MinIO/COS + 本地回环网关（独立于生产网关）

在 `sdk/python` 安装 `.[dev,storage-e2e]` 后，安全注入已有卷的存储访问环境变量，执行：

```sh
CUBE_VOLUME_BACKEND_E2E=1 python3 -m pytest -q tests/test_volume_storage_e2e.py --run-e2e
```

只配置一种存储时使用 `-k minio` 或 `-k cos`。所需变量和清理范围见
[Python 中文 README](../sdk/python/README.zh.md#直通卷-e2e-测试)。两套用例写入
`volumes/<volumeID>/sdk-direct-probe/` 下随机对象，经 SDK 读取真实存储字节后
仅清理自身对象；不删除卷/桶。回环服务伪造网关的元数据和 token，**不能替代**
下述真实网关、卷级凭证和隔离/租约验收。

## 2. 阶段二：真实网关只读验证（核心）

通过环境安全注入配置后执行：

```sh
python3 -m pytest -q tests/test_volume_direct_e2e.py --run-e2e
```

必填：`CUBE_VOLUME_API_URL`（或 `E2B_VOLUME_API_URL`）、`CUBE_VOLUME_ID`、
`CUBE_VOLUME_CONTENT_TOKEN`、`CUBE_VOLUME_TEST_PATH`。

建议同时设置 `CUBE_VOLUME_TEST_SHA256`，校验读到的数据与预期一致。文本格式验证
可另设 `CUBE_VOLUME_TEXT_PATH`。

逐项确认：

1. 字节读取内容与预期摘要一致。
2. 流式读取结果与缓冲读取一致，且含 NUL/非 UTF-8 的二进制不被破坏。
3. 元数据字段完整：name/type/path/size/mode/uid/gid/atime/mtime/ctime/target，
   时间为 datetime，type 为 `unknown/file/directory/symlink`。
4. `depth` 语义正确；未指定与 `depth=0` 返回形状符合合同。
5. 路径不存在时读取抛路径异常，`exists` 返回 false。
6. 非法凭证返回 401/403，不被转成 false。
7. 逐次地址、token、headers 生效，且不携带管理 key 或沙箱 access token。
8. 提前关闭流后连接释放，可再次读取。

**此阶段全部只读**，不创建/删除卷，不启动沙箱。

## 3. 阶段三：验证“确实没有启动沙箱”

这是本期最关键、也最容易误判的一项。

必须同时给出两类证据：

1. **客户端证据**：E2E 用例拦截 SDK 沙箱创建/连接入口，并拦截非卷 HTTP 路由。
   仅此不足以证明服务端行为。
2. **服务端证据**：在服务端日志/指标中确认读取期间没有沙箱、VM、容器创建记录；
   只有存储挂载/租约获取与释放。

允许的行为：存储插件建立宿主机挂载、复用已挂载路径、获取读取租约。
不允许的行为：为了取得文件内容而创建临时沙箱、启动 VM/容器、执行沙箱内命令。

判负条件：只要读取链路依赖沙箱或容器，无论客户端测试是否通过，都不能算直通实现。

## 4. 阶段四：安全与边界验证

这些项目无法由当前 SDK 本地测试覆盖，需要针对服务端执行：

- 跨卷访问：用 A 卷凭证读取 B 卷路径，应被拒绝。
- 跨租户：不同租户凭证访问同一卷，应被拒绝。
- 过期/撤销凭证：过期后读取应失败，不返回数据。
- 路径穿越：`../`、`%2e%2e`、编码绕过等应被拒绝。
- 符号链接逃逸：指向卷外的链接应被拒绝或限制在卷根目录内。
- 租约并发：并发读取不应重复错误挂载；失败回滚、重启回收需幂等。
- 删除协调：活动读取期间或之后删除卷，不应破坏进行中的传输或残留挂载。
- 只读凭证：只读 token 写操作应被服务端拒绝，不能只靠客户端限制。

通过标准：全部拒绝或安全处理，且不泄露宿主机路径或跨卷数据。

## 5. 阶段五：已有管理 API 与写入验证（可选）

管理面验证单独开启 `CUBE_VOLUME_TEST_MANAGEMENT=1`，并提供管理地址与所需凭证。
只调用已有 list/get_info/connect，**不创建或销毁卷**。

写入验证单独开启 `CUBE_VOLUME_E2E_WRITE=1`，需具备读写权限。仅在唯一
`sdk-e2e-*` 测试目录内建目录、写文件、改元数据、删除；清理失败会报告待手动
删除的路径；**不会删除传入的卷**。进程崩溃可能残留测试数据，需人工确认。

可选设置 `CUBE_VOLUME_WRITE_ROOT` 指定测试目录的父目录。

## 6. 阶段六：性能与稳定性观察

- 大文件不宜用缓冲读取；应使用流式读取，避免占用与文件等大的内存。
- 观察并发读取时的连接与租约行为；确认不存在句柄或挂载泄漏。
- 记录超时、限流、重试表现；确认错误不会被静默转换为空结果。
- 注意：当前每次内容调用独立创建并关闭 HTTPX 客户端，**没有跨调用连接池复用**。
  高频小文件场景需评估连接开销，这属于实现权衡，不是故障。

## 7. 判定与结论

| 结论 | 条件 |
|---|---|
| SDK 协议层通过 | 阶段一、二全部通过 |
| 直通成立 | 阶段二通过，且阶段三获得服务端“无沙箱/VM/容器创建”证据 |
| 可上线 | 直通成立，且阶段四全部通过、阶段六无泄漏 |
| 不成立 | 读取依赖沙箱/VM/容器，或存在跨卷/越权/穿越/符号链接逃逸，或租约与删除协调失败 |

任何阶段失败时，先区分是**客户端协议问题**还是**服务端能力缺失**。仅修复客户端
不能让缺少内容网关的部署通过验收；同样，不应通过启动沙箱来掩盖服务端缺失。

- Python 卷相关本地回归与回环 harness 已通过；真实存储测试默认跳过。
- 此前独立的 COS/MinIO 探针读到真实对象字节；新参数化测试的**真实存储执行结果另记**，不能沿用旧探针结论。
- 本地回环网关运行同一真实网关 E2E：只读与写入模式此前均通过；未连接生产网关。

- 服务端“未启动沙箱”的观测证据。
- 跨卷、跨租户、过期凭证、路径穿越、符号链接逃逸等安全项。
- 租约并发、重启回收、删除协调。
- Node/Go 本轮未重新验证；严格总传输期限与完整 E2B 差分未验证。

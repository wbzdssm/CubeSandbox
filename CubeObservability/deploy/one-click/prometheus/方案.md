# Prometheus 沙箱指标后端

本目录提供两种接入方式，均只处理 Cubelet 暴露的 `cubesandbox_*` 沙箱资源指标：

1. `install.sh`：安装 Prometheus `3.13.4 LTS`，接收节点 OTel Collector 的
   OTLP/HTTP 或 Prometheus Remote Write。
2. `render.sh`：为已有 Prometheus 生成直接抓取 Cubelet 的 `scrape_configs`。

不采集节点 CPU、内存、磁盘或网络等宿主机资源指标。

## 1. 安装接收端

```bash
sudo ./CubeObservability/deploy/one-click/prometheus/install.sh install
```

默认：

- 监听 `:9092`，避开 `cube-proxy` 的 `:9090`。
- 开启 `--web.enable-otlp-receiver`。
- 开启 `--web.enable-remote-write-receiver`。
- `scrape_configs: []`，避免 Prometheus 自身或 Cubelet 被重复抓取。

节点 Collector 可选择：

```bash
# OTLP/HTTP 基础地址；Collector 自动追加 /v1/metrics
CUBE_METRICS_OTLP_HTTP_ENDPOINT=http://<prometheus-ip>:9092/api/v1/otlp

# 或 Remote Write 完整地址
CUBE_METRICS_REMOTE_WRITE_URL=http://<prometheus-ip>:9092/api/v1/write
```

## 2. 已有 Prometheus 直接抓取

```bash
env \
  CUBE_OBSERVABILITY_CLUSTER_ID=prod \
  CUBE_SANDBOX_NODE_IP=10.0.0.20 \
  CUBE_METRICS_PROM_CONFIG=/tmp/cubesandbox-prometheus-scrape.yml \
  ./CubeObservability/deploy/one-click/prometheus/render.sh
```

生成的核心配置：

```yaml
scrape_configs:
  - job_name: cubesandbox-resource
    metrics_path: /v1/metrics/resource
    static_configs:
      - targets: ["10.0.0.20:9998"]
        labels:
          cluster: prod
          node: 10.0.0.20
```

Cubelet `:9998` 没有内置 TLS 和鉴权。直接抓取时应只允许 Prometheus 从受信管理
网络访问；标准节点 Collector 使用回环地址抓取，可避免暴露该端口。

## 3. 检查

```bash
curl -fsS http://127.0.0.1:9092/-/ready
curl -fsS http://127.0.0.1:9092/api/v1/query \
  --data-urlencode \
  'query=sum(cubesandbox_node_sandbox_count or on (cluster, node) count by (cluster, node) (cubesandbox_host_sandbox_memory_current_bytes))'
```

Grafana 沙箱资源看板只查询 `cubesandbox_node_sandbox_*` 和
`cubesandbox_host_sandbox_*` 指标。正式发布的 `v0.7.0 ~ v0.7.2` 没有节点计数
指标，上述查询会在存在活跃沙箱资源序列时回退到 `count(...)`；空节点可能返回 No data。
